# プロダクト要求定義書 — kaori_kabu

## プロダクトビジョンと目的

kaori_kabu は、株式投資の素人であるかおりんが、世界トップ投資家の手法（Magic Formula、13F Cloning、ファクター投資）と統計的リスク管理（Half-Kelly、Monte Carlo、HMM レジーム検出）を AI で活用し、米国株 + 日本株を多角的視点（短期トレード、長期投資、配当）で分析・運用するための **個人専用ローカルダッシュボード**。情報優位性・執行速度・レバレッジで機関投資家には勝てない前提で、**規律と統計** で個人投資家の平均を確実に超えることを目指す。

## ターゲットユーザー

### プライマリーユーザー

- **ペルソナ**: かおりん（30 代、トヨタ自動車生産技術エンジニア、株運用は素人、ハイリスク嫌い、Python / TypeScript 開発スキルあり）
- **現状の課題**:
  - 個別銘柄分析に時間を取られすぎる
  - 利確・損切りタイミングの判断に迷う
  - トップ投資家の手法を体系的に学ぶ手段がない
  - 短期・長期・配当の複数視点を統合的に管理できない
- **解決したいニーズ**:
  - **保有銘柄の状況を一画面で把握**（含み益損、リスク、利確タイミング）
  - **データドリブンの売買判断**（感情ではなく統計）
  - **学びながら運用**（教育レイヤー付きシグナル）
  - **複数戦略の同時運用**（Magic Formula バリュー + 13F Cloning + 配当）

## 成功の定義

- **ユーザー指標**: 銘柄分析所要時間 30 分 → 5 分（OpenBB SDK + ダッシュボード）
- **プロダクト指標**: 6 ヶ月で 7 機能すべて週 1 回以上利用、保有銘柄 10 銘柄を一覧管理
- **運用指標**: 1 年後のポートフォリオ Sharpe > 0.8、Max Drawdown < 25%

## ビジネス要件

- **金商法対象外**: 完全に個人専用ローカル、他者にデータ・シグナルを提供しない
- **データ正確性**: API データ提供元（EODHD / J-Quants / SEC）の遅延・誤りに対し検証ロジックを持つ
- **再現性**: 同じパラメータで再実行すれば同じ結果（バックテスト、スクリーナー）
- **教育目的**: 各シグナルに学術的バックボーンと素人向け解説を必ず併記

## ユーザーストーリー

### US-001: Magic Formula で割安銘柄を発見

**ユーザーとして、** Magic Formula スクリーナーで米国・日本市場から ROC と Earnings Yield が高い上位 30 銘柄を抽出 **したい。それによって、** Greenblatt の手法に従い長期で年率 15%+ を狙える銘柄候補リストが手に入る。

**受け入れ条件**:
- [ ] 米国・日本市場から銘柄取得（金融・公益・エネルギー除外）
- [ ] 時価総額 $100M 以上のフィルタ
- [ ] ROC スコア + Earnings Yield スコア合計でランキング
- [ ] 各銘柄に詳細リンク（学術的根拠、リスク警告、Value Trap 警告含む）
- [ ] 四半期リバランスタイミングの自動アラート
- [ ] CSV エクスポート機能

### US-002: トップ投資家のポジションを追従

**ユーザーとして、** Berkshire / Pabrai / Burry / Ackman の最新 13F filings に基づくポジション一覧を見 **たい。それによって、** 個人では得られない情報優位性を 45 日遅延で借りられる。

**受け入れ条件**:
- [ ] SEC EDGAR から 13F-HR を四半期取得（CIK ベース）
- [ ] ファンド別 × 銘柄ベースの保有マトリックス
- [ ] 前四半期からの差分（新規買い / 増加 / 減少 / 売却）強調表示
- [ ] 「スーパー集中ファンド」（保有 5 銘柄以下）優先表示
- [ ] 各ポジションに直近株価・Magic Formula スコアを併記

### US-003: ポートフォリオの将来分布を確率で見る

**ユーザーとして、** 現在の保有ポートフォリオが 1 年後にいくらになるかを 1000 パスのモンテカルロで分布表示 **したい。それによって、** 「100 万円 → 平均 110 万円」の点予測ではなく「90% 確率で 80〜140 万円」の現実的な期待値が分かる。

**受け入れ条件**:
- [ ] GBM（幾何ブラウン運動）パスを 1000 本生成
- [ ] 5 / 25 / 50 / 75 / 95 パーセンタイル fan chart
- [ ] 過去のヒストリカル誤差を併記
- [ ] 異なるホライズン（1 / 3 / 6 / 12 ヶ月）切り替え

### US-004: Half-Kelly でポジションサイズ自動計算

**ユーザーとして、** 各銘柄の勝率と損益比から **数学的に最適な** ポジションサイズ × 0.5 を自動算出 **したい。それによって、** 過剰投資による破滅リスクを回避できる。

**受け入れ条件**:
- [ ] バックテストから勝率 / 平均利益 / 平均損失を抽出
- [ ] `f* = (bp - q) / b × 0.5` で Half-Kelly 算出
- [ ] 1 銘柄上限 5%、現金準備 10% 強制
- [ ] 入力時に「フル Kelly でなく Half-Kelly を使う理由」を表示

### US-005: リスク指標を一画面で確認

**ユーザーとして、** ポートフォリオ全体の Sharpe / Sortino / Calmar / Max DD / VaR / CVaR を一画面で **したい。それによって、** リスク調整後リターンの善し悪しが瞬時に分かる。

**受け入れ条件**:
- [ ] QuantStats `qs.reports.html()` 連携
- [ ] 各指標に素人向け説明文（「Sharpe = リターン÷リスク」等）
- [ ] ベンチマーク（東証 / S&P500）との比較
- [ ] 個別銘柄寄与度ブレークダウン

### US-006: マーケット環境を 3 段階で自動判定

**ユーザーとして、** 現在の市場が Bull / Choppy / Crisis のどの状態かを HMM が自動判定し信号灯表示 **したい。それによって、** Crisis 時には新規買いを控え現金比率を上げる規律を保てる。

**受け入れ条件**:
- [ ] log_returns + realized vol + VIX を hmmlearn に投入
- [ ] 過去 2 年（504 営業日）から学習
- [ ] 状態遷移確率も表示
- [ ] 緑 / 黄 / 赤の信号灯 UI

### US-007: 損切り規律を強制リマインド

**ユーザーとして、** 各保有銘柄の ATR トレーリングストップ価格を計算し、価格が下回ったら UI で赤信号 **したい。それによって、** Loss Aversion バイアスに勝ち、機械的に損切りできる。

**受け入れ条件**:
- [ ] ATR(14) × 2.5 でストップ計算
- [ ] ピーク価格からのトレーリング
- [ ] 抵触銘柄を Streamlit 上で目立つ位置に表示
- [ ] Decision Log への自動記録（「ATR 抵触 → 売却シグナル」）

### US-008: Polymarket でマクロイベント確率を監視

**ユーザーとして、** Polymarket で取引されている Fed 利上げ・米選挙・景気後退の確率を取得 **したい。それによって、** 市場の織り込み期待値を客観的に把握できる。

## 機能要件

### 入出力仕様（主要機能）

**Magic Formula スクリーナー**:
- 入力: 市場（米国 / 日本 / 両方）、最低時価総額、除外セクター、上位 N
- 出力: pandas.DataFrame（ticker, name, ROC, EY, MF score, sector, market_cap）

**13F Cloning**:
- 入力: 追跡対象 CIK リスト、四半期
- 出力: pandas.DataFrame（fund_name, ticker, shares, value_usd, change_qoq）

**Monte Carlo**:
- 入力: 過去リターン系列、ホライズン、シミュレーション数
- 出力: numpy.ndarray (shape: simulations × horizon)、パーセンタイル統計

### エッジケース

- API レート制限超過 → tenacity リトライ
- 銘柄ティッカーが市場間で重複（例: DELL は米日両方）→ exchange サフィックスで区別
- 配当再投資の扱い → adj_close を使用、明示
- ストックスプリット → adj_close で自動補正
- 為替変換 → 取得時の為替レートを記録、現在価値計算は最新レート

## スコープ外（明示的に含まない）

- **自動売買** — 売買判断は必ずかおりん本人が実施、API 経由の発注は実装しない
- **公開ダッシュボード** — 完全に個人ローカル運用、SaaS 化しない
- **モバイルアプリ** — Streamlit のレスポンシブ表示で代替
- **暗号資産** — 株式に集中、暗号資産は対象外（Phase 3 以降検討）
- **オプション・先物** — Phase 3 以降検討
- **HFT・スキャルピング** — 個人で勝てない領域なので意図的に除外

## リスクと前提

| カテゴリ | 内容 | 対策 |
|---|---|---|
| 技術リスク | EODHD / J-Quants の API 規約変更 | OpenBB SDK で抽象化、複数プロバイダ切替可能に |
| 技術リスク | API レート制限 | キャッシュ + tenacity リトライ + ratelimit デコレータ |
| データリスク | 過去データの誤り（生存者バイアス含む） | 複数ソースで検証、公式 EDGAR を正本に |
| 戦略リスク | Magic Formula は近年 5 年アンダーパフォーム | バックテスト範囲を 20+ 年で評価、規律を保つ |
| 戦略リスク | AI 予測の過信（Overconfidence） | 必ず確率分布で表示、点予測禁止 |
| 法的リスク | 公開すると金商法対象 | 個人ローカル運用を厳守、`.gitignore` で公開防止 |
| 心理的リスク | Loss Aversion で損切り遅れ | ATR ストップ強制、Decision Log で振り返り |
